
# Guinea Pig

![Guinea Pig](guinea-pig.png)

## Description
This repo is a **security-scanner test bed**: intentionally-vulnerable fixtures,
**one CWE per directory**, each paired with its remediation, plus a running web
service for dynamic (DAST) testing, a context-stripped set for LLM-based
detection, and Agent-skill fixtures for skill scanners.

### Layout
```
static/CWE-<n>/<language>/vulnerable.<ext>   # vulnerable fixture — the path IS the ground truth
static/CWE-<n>/<language>/patched.<ext>      # the remediation (a negative: expect no finding)
static/CWE-798/catalogue/<provider>/*.txt    # per-rule secret examples (positives — secret-scanner recall)
static/CWE-798/false-positives/*             # benign code that resembles a rule (negatives — precision)
pipeline/sca/<eco>/<manifest>                # vulnerable dependency manifests (SCA)
pipeline/sca/bumpy/                          # project pinning pyyaml==3.13 (SCA + CWE-502 yaml.load)
pipeline/ci/<platform>/...                   # realistic CI files (plumber / poutine)
dynamic/                                     # runnable Express service for DAST (+ openapi.yml)
llm/<language>/<uuid>.<ext>                  # context-stripped twins for LLM-based detection
skills/{malicious,benign}/<name>/SKILL.md    # Agent-skill fixtures for skill scanners
benchmark/ground-truth/<theme>.json          # centralized ground truth (one file per theme)
```
`static/CWE-89/python/vulnerable.py` is expected to be flagged as CWE-89.

- **static / SAST** — languages: java, c, cpp, csharp, python, javascript
- **static / IAC** — languages: terraform, ansible, kubernetes
- **static / PIPELINE** — languages: github, gitlab (per-CWE snippets)
- **static / SECRET** — env, ini, conf, pem (hard-coded secrets / private key), plus
  a **catalogue** of 1028 per-rule secret examples and 21 **false-positive** look-alikes
  under `static/CWE-798/` (see their `README.md`s)
- **pipeline / SCA + CI** — `pipeline/sca/` (vulnerable deps) and `pipeline/ci/`
  (whole `.gitlab-ci.yml` / `.github/workflows/`) — see `pipeline/README.md`
- **dynamic / DAST** — `dynamic/` Express app, one CWE-annotated route per endpoint
- **llm** — `llm/` context-stripped, UUID-renamed twins (98 files) for LLM-based detection
- **skills** — `skills/` malicious + benign Agent-skill fixtures for skill scanners (e.g. ai-cisco-skill-scanner)

Each fixture's detecting scanner family (SAST/IAC/PIPELINE/SECRET/DAST/SCA/SKILL)
is recorded in the catalog (`scanner_types`).

### Ground truth & benchmark
- `benchmark/ground-truth/<theme>.json` — the **uniform per-theme ground truth**,
  centralized (one file each for static, pipeline, dynamic, llm, skills):
  `positives` (+ the `secret_catalogue`) and `negatives`. Generated by
  `benchmark/src/build_report.py` (re-run after adding fixtures).
- `benchmark/INVENTORY.md` — human recap: CWE × language matrix and totals.
- `benchmark/GROUND-TRUTH.md` — schema + update procedure.
- `benchmark/` — runs scanners and compares their findings against the merged
  ground truth, reporting **detection coverage** (recall over positives) and
  **errors** (false positives on `patched.*` / look-alikes / benign skills, plus
  noise):
  ```bash
  python3 benchmark/src/build_report.py                            # refresh ground truth
  uv run python benchmark/src/benchmark.py install --all                 # install scanner tools
  uv run python benchmark/src/benchmark.py run                           # run scanners + score (all themes but dast)
  ```
  The scanners themselves are vendored under `benchmark/src/dsbench/` and run
  in-process; see `benchmark/README.md` for modes, the recap/top-3 tables, and
  the `.env` scanner toggles.
- `dynamic/README.md` — how to run and scan the DAST target, plus exposure warnings.

## Adding a vulnerability (so `build_report.py` picks it up)

> **Golden rule:** the `benchmark/ground-truth/*.json` files are **generated**, not
> hand-written. **Never edit them by hand** — they'd be overwritten. The *fixture*
> (plus, for the non-derivable bits, a small sidecar) is the source of truth.
> Add the fixture, then run the generator and check the counts it prints:
>
> ```bash
> python3 benchmark/src/build_report.py
> ```

What you add depends on the kind of fixture:

**Static code vuln (SAST / IaC / SECRET / pipeline snippet)** — fully derived from
the path + a header, no JSON/sidecar edit:
1. Create `static/CWE-<n>/<language>/vulnerable.<ext>` **and** its `patched.<ext>`
   sibling (the patched file becomes a "must-not-flag" negative automatically).
   - `CWE-<n>` in the path **is** the ground-truth CWE.
   - `<language>` (the folder) selects the scanner family: `java,c,cpp,csharp,python,javascript` → **SAST**; `terraform,ansible,kubernetes` → **IaC**; `github,gitlab` → **PIPELINE**; `env,ini,conf,pem` → **SECRET**. (Hard-coded-credential CWEs — 798/321/259/256 — are also tagged SECRET.)
2. Put a 3-line header at the top (in that language's comment style), e.g. for Python:
   ```python
   # CWE-89: Improper Neutralization of Special Elements used in an SQL Command (SQL Injection)
   # Builds a SQL query by concatenating untrusted request input.
   # Vulnerable sink: cursor.execute(f"... {user_input} ...")
   ```
   The generator reads the `CWE-<n>:` line (name), the next line (description) and
   the `... sink:` line.
3. **New CWE?** Add it to `CWE_INFO` in `benchmark/src/build_report.py` (canonical
   name + default severity) — otherwise it has no name/severity.

**Benign look-alike (a precision test, must-not-flag)** — drop a file under
`static/CWE-798/false-positives/` with a `Resembles:` / `Why benign:` header.

**Secret catalogue entry** — drop a `.txt` under
`static/CWE-798/catalogue/<provider>/` (counts as a CWE-798 SECRET positive).

**SCA manifest / whole-file pipeline project** — these aren't path-derived: add the
manifest path (and any source-level sink) to the `SCA_MANIFESTS` / `PIPELINE_SAST`
tables in `benchmark/src/build_report.py`.

**CI/CD fixture** — drop the file under `pipeline/ci/<platform>/…` and **mention each
CWE in a comment** inside it (e.g. `# CWE-94: …`); the generator emits one positive
per distinct `CWE-<n>` it finds in the file.

**DAST endpoint** — add the route to `dynamic/app.js` **and** the path to
`dynamic/openapi.yml` with `x-cwe:` + `x-vuln:` (+ `summary:`). It is graded by
endpoint (the openapi spec also drives the active zap/nuclei scans).

**LLM twin** — the opaque `uuid → source` map can't be derived from the tree: add a
row `{file, language, source}` to `benchmark/src/llm_sources.json` pointing at the
original fixture. The generator copies that fixture's weaknesses onto the twin.

**Skill fixture** — drop `skills/{malicious,benign}/<name>/SKILL.md` (no in-file
"malicious" marker — by design) and add its verdict to
`benchmark/src/skills_labels.json` (`label: flag|benign`, `category`, `severity`,
`indicators`).

Then regenerate (`python3 benchmark/src/build_report.py`) and re-run the benchmark.
Full schema + field reference: `benchmark/GROUND-TRUTH.md`; recap & totals:
`benchmark/INVENTORY.md`.


## VSCode configuration
The MCP server is declared in `.vscode/mcp.json` (`security-mcp-server` →
`http://127.0.0.1:8000/mcp/`). Open VSCode's MCP **Servers** view and **Start** it.
You may need to be signed in to GitHub Copilot for it to work.

## Claude code configuration 
```
claude mcp add --transport http --scope project my-serveur http://127.0.0.1:8000/mcp/
```

## Sources
- **SAST / SCA base fixtures** — adapted from
  https://github.com/dehvCurtis/vulnerable-code-examples
- **Hard-coded-secret config fixtures** (`env`, `ini`, `conf`, `pem`) — drawn from
  https://github.com/Yelp/detect-secrets/tree/master/test_data
- **CWE-798 secret catalogue** (`static/CWE-798/catalogue/`, 1028 per-rule examples)
  — generated from the regex rule packs of kingfisher, titus, noseyparker,
  gitleaks and betterleaks in the sibling `../secret-rules` repo. The benign
  look-alikes in `static/CWE-798/false-positives/` are hand-written.
